# Lua障害物回避 実機手順

更新日: 2026-07-26

対象: CC-02、Pixhawk 6C Mini、ArduRover 4.6.3、前方TF-Luna

## 目的

前方障害物を検知したときに、Luaが次の一連の動作を行うことを確認する。

```text
接近
  -> 減速
  -> 停止
  -> 短距離後退
  -> 固定方向へ旋回
  -> 前方を再確認
  -> 元のGuided目標へ復帰
```

使用するLua:

```text
docs/03_Lua障害物回避/Scripts/luaoa_guided_avoid_rover463.lua
```

通常運用へ戻すパラメータ:

```text
params/04_webapp_ts/20260720_01_webapp_rc1_steering_rc3_throttle.param
```

## 1. 試験設定

Mission Plannerで現在のフルパラメータを保存してから、次を設定する。

```text
SCR_ENABLE        = 1
SCR_USER1         = 3
RTUN_ENABLE       = 0
AVOID_ENABLE      = 0
AVOID_BACKUP_SPD  = 0
WP_SPEED          = 0.3
```

`AVOID_ENABLE=0`は、ArduPilot標準OAとLuaの動作を重ねないための試験設定である。

`RTUN_ENABLE=0`は現行パラメータファイルに合わせてQuikTuneを無効のままにする設定である。
実機用Lua v3は`RTUN_ENABLE`を起動条件にしていないため、QuikTune Luaを削除済みなら、
実機値が`1`でも障害物回避Luaは`FAULT`にしない。

### Mission PlannerからLuaを配置する

作業中はRoverをDisarmし、走行用バッテリーを外しておく。PixhawkはUSB給電だけで起動する。

1. Mission PlannerをPixhawkへ接続する。
2. 上部メニューから`CONFIG`を開く。
3. 左側メニューの`MAVFTP`を開く。
4. ファイル一覧を更新し、SDカードのルートにある`APM`を開く。
5. `APM/scripts`を開く。

`scripts`フォルダが存在しない場合:

1. `CONFIG`の`Full Parameter List`で`SCR_ENABLE=1`を設定する。
2. `Write Params`で書き込む。
3. Pixhawkを再起動する。
4. 再接続して`CONFIG` → `MAVFTP` → `APM`を開き、`scripts`が作成されたことを確認する。

#### 既存Luaを退避する

`APM/scripts`に`.lua`ファイルがある場合は、先にPCへ保存する。

1. `APM/scripts`内のファイル名とサイズを記録する。
2. 各`.lua`を選択し、Mission PlannerのDownload操作でPCへ保存する。
3. 保存先を次のような日付入りフォルダにする。

   ```text
   backup/APM_scripts_YYYYMMDD/
   ```

4. PC側にファイルが存在し、サイズが0 byteでないことを確認する。
5. バックアップできた`.lua`を`APM/scripts`から削除する。
6. 一覧を更新し、`.lua`が残っていないことを確認する。

Mission Plannerの版によってボタン表示が`Download`、`Get`など異なる場合がある。ファイルをPCへ取得する操作を使用する。フォルダ自体やログなど、`.lua`以外のファイルは削除しない。

#### 実機用Luaをアップロードする

1. `APM/scripts`を開いた状態でUpload操作を選ぶ。
2. PC側で次のファイルを選択する。

   ```text
   docs/03_Lua障害物回避/Scripts/luaoa_guided_avoid_rover463.lua
   ```

3. 転送完了までMission Plannerを切断しない。
4. MAVFTPの一覧を更新する。
5. 次を確認する。

   ```text
   APM/scripts/luaoa_guided_avoid_rover463.lua
   ```

6. ファイル名の末尾が`.lua`であり、`.lua.txt`になっていないことを確認する。
7. ファイルサイズが0 byteでないことを確認する。
8. `APM/scripts`に存在する`.lua`が、この1本だけであることを確認する。

Pixhawkを再起動する。再接続後、Mission Plannerの`DATA`画面にあるMessagesで次を確認する。

```text
LUAOA463: loaded 20260726-rover463-staged-v4
LUAOA463: SCR_USER1 0=monitor 1=stop 2=back 3=full
```

表示されない場合:

- `SCR_ENABLE=1`が書き込まれているか確認する。
- MAVFTPでファイルが`APM/scripts`直下にあるか確認する。
- ファイル名が`.lua`で終わっているか確認する。
- 他のLuaが同時に置かれていないか確認する。
- Messagesに`Scripting`、`Lua`、`out of memory`などのエラーがないか確認する。
- `reboot`だけで反映されない場合は、Disarmと走行用バッテリー切断を確認してからPixhawkを電源再投入する。

### 物理SDカードを使う場合

MAVFTPを使わず、PixhawkのmicroSDカードへ直接コピーしてもよい。

1. RoverをDisarmし、USBと走行用バッテリーを外す。
2. Pixhawkの電源が切れてからmicroSDカードを抜く。
3. PCでSDカードを開く。
4. `APM/scripts`内の既存LuaをPCへバックアップする。
5. `APM/scripts`から既存の`.lua`を外す。
6. `luaoa_guided_avoid_rover463.lua`を`APM/scripts`へコピーする。
7. `.lua`がこの1本だけであることを確認する。
8. OSの「取り出し」を実行してからSDカードを抜く。
9. SDカードをPixhawkへ戻し、Pixhawkを起動する。
10. Mission PlannerのMessagesで起動識別文字列を確認する。

## 2. 距離確認

TF-Luna正面の1～3 mに板を置き、Mission Plannerの距離表示とLua表示が概ね一致することを確認する。

```text
LUAOA463: monitor ... m st=... lv=3
```

板を近づけると表示距離が小さくなればよい。距離が100倍または1/100になる、値が固定される、距離が出ない場合は走行しない。

## 3. 障害物の配置

- 平坦で石や草の少ない場所を使う。
- TF-Lunaが捉えやすい自立式の板を障害物にする。
- 障害物の左右と後方に、Roverが旋回できる空間を残す。
- Guided目標は障害物の先へ設定できる位置にする。
- 人や車両を障害物として使用しない。

Roverは固定方向へ旋回する。障害物の横に壁、段差、車両などがないことを確認する。

## 4. 回避走行

1. 送信機を保持し、HOLDとDisarmをすぐ操作できる状態にする。
2. Roverを障害物から3.5 m程度離し、正面を障害物へ向ける。
3. HOLDでArmする。
4. Guidedへ変更する。
5. Mission Plannerで障害物の先へGuided目標を送る。
6. 次のログを確認する。

   ```text
   LUAOA463: guided target ready via ...
   LUAOA463: control level 3 latched
   LUAOA463: IDLE -> CLEAR: guided target ready
   ```

7. Roverが最大0.3 m/sで障害物へ接近することを確認する。
8. 約3 mで減速し、約2 mで停止することを確認する。
9. 停止後、短距離後退して固定方向へ旋回することを確認する。
10. 旋回後の前方が3.5 m以上空いていれば、元のGuided目標へ復帰することを確認する。

正常時の状態遷移:

```text
LUAOA463: CLEAR -> SLOW
LUAOA463: SLOW -> STOP
LUAOA463: STOP -> BACKUP
LUAOA463: BACKUP -> TURN
LUAOA463: TURN -> RECHECK
LUAOA463: RECHECK -> RESUME
LUAOA463: RESUME -> CLEAR: target restored
```

旋回後も前方が塞がっている場合:

```text
LUAOA463: RECHECK -> BACKUP: d=... st=... try=1
```

SITL版と同じく、後退、旋回、前方再確認を最大5回まで繰り返す。
5回目でも前方が3.5 m未満なら、`FAULT max tries`で停止保持となる。

## 5. 合格条件

- Lua表示とTF-Lunaの実距離が概ね一致する。
- 障害物へ接触せず、減速して停止する。
- 後退と旋回が設定時間で終了する。
- 旋回後に前方が空いている場合だけ走行を再開する。
- `RESUME -> CLEAR: target restored`が出る。
- HOLDとDisarmで試験を終了できる。

## 6. 終了と復帰

1. HOLDへ変更する。
2. Disarmする。
3. 走行バッテリーを外す。
4. Mission Plannerの`CONFIG` → `MAVFTP` → `APM/scripts`を開く。
5. `luaoa_guided_avoid_rover463.lua`をPCへ保存するか、リポジトリに同じファイルがあることを確認してからSDカード上のファイルを削除する。
6. 試験前に退避したLuaを通常運用でも使用する場合は、`backup/APM_scripts_YYYYMMDD/`から`APM/scripts`へ戻す。
7. MAVFTPの一覧を更新し、試験Luaが残っていないことを確認する。
8. 次の現行パラメータを読み戻す。

   ```text
   params/04_webapp_ts/20260720_01_webapp_rc1_steering_rc3_throttle.param
   ```

9. Pixhawkを再起動する。
10. Messagesに`LUAOA463: loaded 20260726-rover463-staged-v4`が出ないことを確認する。
11. 次の値が戻っていることを確認する。

   ```text
   RCMAP_ROLL        = 1
   RCMAP_THROTTLE    = 3
   RC7_OPTION        = 153
   AVOID_ENABLE      = 7
   AVOID_MARGIN      = 1
   AVOID_BACKUP_SPD  = 0.2
   RNGFND1_MAX_CM    = 400
   RTUN_ENABLE       = 0
   SCR_USER1         = 0
   WP_SPEED          = 0.9776623
   ```

## 中止条件

次の場合はHOLDへ変更し、停止後にDisarmする。

- 距離表示が実距離と合わない。
- 意図しない方向へ後退または旋回する。
- 障害物へ接触しそうになる。
- `LUAOA463: internal error`が出る。
- RoverがFAULT後も停止しない。
