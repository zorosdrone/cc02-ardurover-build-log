## 写真から確認できること

- 現行FCは Pixhawk 2.4.8Pro / Pixhawk Pro 系の上面ポート構成。
- `POWER`、`TELEM`系、`GPS`、`I2C`、`SWITCH`、`BUZZER` 付近に接続がある。
- `MAIN OUT 1` にステアリングサーボ、`MAIN OUT 3` にESC / スロットルが接続されている。
- 受信機は RadioLink R8EF V1.6 で、`S.BUS / CH1` に接続されている。
- コンパニオンコンピュータ系は旧FCではTELEM2接続。6C Mini換装後は`TELEM1`へ移行済み。
- M8N GPSはGPSポート、Compass系はI2Cポートへ分かれて接続されている。
- LiDAR / RangeFinderは現行パラメータ上 `SERIAL4_PROTOCOL=9`, `SERIAL4_BAUD=115` のため、現行FCのSERIAL4系に接続されている扱い。
- Pixhawk 6C miniへ換装する前に、コネクタが刺さるかではなく、各信号のピン順を実測・目視で確認する必要がある。

## GPS2 6ピン変換メモ

現行M8Nの2股配線を、Pixhawk 6C Miniの`GPS2` 6ピンへまとめる。

| GPS2側信号 | 接続する現行M8N側 | 注意 |
| --- | --- | --- |
| `VCC` | GPS UART系またはCompass I2C系の5V | 5Vは共通化する。重複給電にならないよう配線を整理する。 |
| `UART TX` | M8N GPS側 `RX` | FCからGPSへ送る線。TX/RXは交差接続。 |
| `UART RX` | M8N GPS側 `TX` | GPSからFCへ送る線。TX/RXは交差接続。 |
| `I2C SCL` | M8N Compass側 `SCL` | SCL同士を接続。 |
| `I2C SDA` | M8N Compass側 `SDA` | SDA同士を接続。 |
| `GND` | GPS UART系またはCompass I2C系のGND | GNDは共通化する。 |

`GPS2` 6ピンへまとめられない場合だけ、`GPS1`または独立`I2C`ポートを予備候補として使う。

### GPSコネクタ作業方針

現行Pixhawk Pro / 2.4.8Pro系セット付属のM8N GPSコネクタを、6C Miniへそのまま流用するのは避ける。
理由は、旧コネクタと6C Mini側JST-GHのハウジング形状、爪位置、接触圧が一致しない可能性があるため。

旧Pixhawk標準GPSポートのピン順:

```text
旧Pixhawk GPS port Pin1 = VCC +5V
旧Pixhawk GPS port Pin2 = TX OUT
旧Pixhawk GPS port Pin3 = RX IN
旧Pixhawk GPS port Pin4 = CAN2 TX / 未使用扱い
旧Pixhawk GPS port Pin5 = CAN2 RX / 未使用扱い
旧Pixhawk GPS port Pin6 = GND
```

GPSモジュール側の信号として見ると、FCのTXはGPSのRXへ、FCのRXはGPSのTXへ入る。
したがって、現行M8N GPS側6ピンは以下として扱う。

```text
M8N GPS側 Pin1 = VCC +5V
M8N GPS側 Pin2 = GPS RX
M8N GPS側 Pin3 = GPS TX
M8N GPS側 Pin6 = GND
```

現行GPS 6ピンケーブルの写真から読める色:

```text
赤 = Pin1 +5V
黄 = Pin2 GPS RX
緑 = Pin3 GPS TX
黒 = Pin6 GND
```

6C Mini `GPS2`へ接続する場合:

```text
6C Mini GPS2 Pin1 VCC      -> 現行GPS 赤 +5V
6C Mini GPS2 Pin2 UART_TX  -> 現行GPS 黄 GPS RX
6C Mini GPS2 Pin3 UART_RX  -> 現行GPS 緑 GPS TX
6C Mini GPS2 Pin4 I2C_SCL  -> GPS単体確認では未接続
6C Mini GPS2 Pin5 I2C_SDA  -> GPS単体確認では未接続
6C Mini GPS2 Pin6 GND      -> 現行GPS 黒 GND
```

2026-06-08:

- 上記配線方針でGPS LED点灯を確認。
- GPSへの5V/GND給電はOK。
- 次はMission Planner上でGPSステータス、衛星数、HDOPを確認する。

選択肢:

| 方法 | 判断 | メモ |
| --- | --- | --- |
| 既存コネクタから端子を抜いて上下反転/差し替え | 非推奨 | 小型端子を壊しやすく、爪保持が甘くなると走行中に接触不良になる。ハウジング形状が違う場合、端子を入れ替えても根本解決にならない。 |
| 現行GPSケーブルを途中で切り、6C Mini用JST-GH 6Pピグテールへ半田付け | 推奨 | 6C Mini側は正規JST-GHを使える。信号名で接続でき、導通確認もしやすい。 |
| M8N側コネクタから完全に作り直す | 予備 | M8N側端子規格が分かる場合のみ。作業量が増える。 |

推奨作業:

1. 現行M8N GPS側ケーブルを、GPS本体側に十分な余長を残して切る。
2. 6C Mini `GPS2`用JST-GH 6Pピグテールを用意する。
3. 現行GPS側の各線を、旧コネクタのピン位置または導通で `5V / RX / TX / GND` として特定する。
4. 以下の対応で半田付けする。

```text
6C Mini GPS2 Pin1 VCC      -> M8N GPS 5V
6C Mini GPS2 Pin2 UART_TX  -> M8N GPS RX
6C Mini GPS2 Pin3 UART_RX  -> M8N GPS TX
6C Mini GPS2 Pin4 I2C_SCL  -> 未接続、またはCompass SCLへまとめる場合のみ接続
6C Mini GPS2 Pin5 I2C_SDA  -> 未接続、またはCompass SDAへまとめる場合のみ接続
6C Mini GPS2 Pin6 GND      -> M8N GPS GND
```

初回確認では、GPS UARTだけを優先してPin1/2/3/6を接続する。
Compass I2Cは、GPSが認識されてから独立`I2C`へ接続するか、`GPS2` Pin4/5へまとめる。

注意:

- 切断前に写真を撮る。
- 1本ずつ半田付けし、熱収縮チューブで絶縁する。
- 通電前に`VCC-GND`ショートがないことを確認する。
- GPSを挿す前に、6C Mini `GPS2`側Pin1-Pin6間が約5Vであることを確認する。
- 通電後、M8N GPS LEDが点灯/点滅することを先に確認する。

## OLED Module I2C実験メモ

現行Pixhawk Proセット付属のOLED Moduleを、Pixhawk 6C Miniの独立`I2C`ポートへ合わせる実験を行う。

2026-06-08: ハンダ後に6C Mini独立`I2C`へ接続し、`NTF_DISPLAY_TYPE=1`を設定して再起動したところ表示成功。

写真上のOLED基板印字:

```text
GND
VCC
SCL
SDA
```

写真上の線色:

```text
GND = 黒
VCC = 赤
SCL = 緑
SDA = 黄
```

Pixhawk 6C Mini独立`I2C`ポート:

```text
Pin1 VCC
Pin2 I2C2_SCL
Pin3 I2C2_SDA
Pin4 GND
```

接続対応:

| OLED Module | Pixhawk 6C Mini `I2C` | 注意 |
| --- | --- | --- |
| `GND` / 黒 | Pin4 `GND` | 導通で確認する。 |
| `VCC` / 赤 | Pin1 `VCC` | 5V給電。 |
| `SCL` / 緑 | Pin2 `I2C2_SCL` | SCL同士。 |
| `SDA` / 黄 | Pin3 `I2C2_SDA` | SDA同士。 |

実験手順:

1. FC電源OFF。
2. OLED Module単体で接続する。GPS/CompassのI2C接続は一旦外しておく。
3. 6C Mini側はJST-GH 4Pの正規ケーブルまたはピグテールを使う。
4. OLED側の`GND / VCC / SCL / SDA`印字に合わせて結線する。
5. 通電前に`VCC-GND`がショートしていないことをテスターで確認する。
6. 通電後、OLEDが点灯するか確認する。
7. Mission Plannerで`NTF_DISPLAY_TYPE`を設定して再起動する。
   - SSD1306なら`1`
   - SH1106なら`2`
8. 表示が出ない場合は、`NTF_DISPLAY_TYPE`をもう一方に変えて再起動する。

注意:

- 既存の旧Pixhawk用4Pコネクタを6C Miniへ無理に刺さない。
- I2Cは複数デバイスを同じバスにぶら下げられるが、初回確認はOLED単体で行う。
- OLED確認後、Compassも同じI2Cに接続する場合は、アドレス衝突や接触不良を切り分ける。

## LiDAR / RangeFinder移行メモ

換装前はLiDAR / RangeFinderが`SERIAL4/5`系に接続されていた。Pixhawk 6C Mini換装後は`SERIAL4`が物理`GPS2`に対応するため、LiDARは`TELEM2`へ移行した。

| パラメータ | 換装前値 | 2026-06-10現在値 | 意味 / 判断 |
| --- | --- | --- | --- |
| `SERIAL4_PROTOCOL` | `9` | `5` | 換装前はRangeFinder。現在は`GPS2`用GPSとして扱う。 |
| `SERIAL4_BAUD` | `115` | `230` | 換装前LiDAR用。現在はGPS2側の履歴値。 |
| `SERIAL2_PROTOCOL` | - | `9` | 現在のTELEM2 RangeFinder設定。 |
| `SERIAL2_BAUD` | - | `115` | 現在のTELEM2 115200bps設定。 |
| `SERIAL5_PROTOCOL` | `-1` | `-1` | 無効。 |
| `RNGFND1_TYPE` | `20` | `20` | TF-Luna / RangeFinder系として扱う。 |
| `RNGFND1_MIN_CM` | `20` | `20` | 最小距離。 |
| `RNGFND1_MAX_CM` | `200` | `700` | `200`は換装前値。現在値`700`はAuto-stop実測、屋外反射条件、GCS表示で採否を決める。 |

Pixhawk 6C MiniではArduPilot上の`SERIAL4`が物理`GPS2`に対応する。LiDARへ`SERIAL4`設定を丸コピーしない。

推奨割り当て:

| 機器 | 6C Mini物理ポート | ArduPilot Serial候補 | 設定候補 | メモ |
| --- | --- | --- | --- | --- |
| Raspberry Pi / MAVLink | `TELEM1` | `SERIAL1` | `SERIAL1_PROTOCOL=2`, `SERIAL1_BAUD=921` | 現行TELEM2相当のMAVLink接続をTELEM1へ移行。2026-06-09 動作確認OK。 |
| LiDAR / RangeFinder | `TELEM2` | `SERIAL2` | `SERIAL2_PROTOCOL=9`, `SERIAL2_BAUD=115` | `TELEM2`でよい。Raspberry Piと同じポートには接続しない。 |
| M8N GPS + Compass | `GPS2` | `SERIAL4` | `SERIAL4_PROTOCOL=5` | `GPS2` 6ピンへGPS UART + I2Cをまとめる。 |

2026-06-09の暫定GPS構成:

```text
M10 GPS 10ピン -> Pixhawk 6C Mini GPS1
Mission Planner表示: 屋内 Not Fix、屋外 3D Fix
```

屋内の`Not Fix`はGPS未認識ではなく、GPSモジュールは認識されているが測位確定していない状態として扱う。
2026-06-09に屋外で`3D Fix`を確認したため、M10 GPSの接続と測位は動作確認OK。

`TELEM2`をRaspberry Piで使い続ける場合は、LiDARを`TELEM1`へ接続して、`SERIAL1_PROTOCOL=9`、`SERIAL1_BAUD=115`にする。どちらでもよいが、1つのUARTポートにRaspberry PiとLiDARを同時接続しない。

### Raspberry Pi GPIO UART -> 6C Mini TELEM1 6ピン作成メモ

Raspberry Pi / MAVLinkは、Pixhawk 6C Miniの`TELEM1`へ接続する。
Pi側は40ピンGPIOヘッダのUART0を使う。

前提:

- Raspberry Piは別電源で給電する。
- 6C Mini `TELEM1`の5VはPiの給電に使わない。
- PixhawkとRaspberry PiのGNDは共通にする。
- UARTのTX/RXはクロス接続する。
- CTS/RTSは使わない。

Pixhawk 6C Mini `TELEM1` 6ピン:

| 6C Mini `TELEM1` Pin | 機能 | Pi側 | 接続 |
| --- | --- | --- | --- |
| Pin1 | `VCC +5V` | - | 未接続。絶縁する |
| Pin2 | `UART_TX` | GPIO15 / RXD0 / 物理Pin10 | 接続。FC TX -> Pi RX |
| Pin3 | `UART_RX` | GPIO14 / TXD0 / 物理Pin8 | 接続。FC RX <- Pi TX |
| Pin4 | `CTS` | - | 未接続 |
| Pin5 | `RTS` | - | 未接続 |
| Pin6 | `GND` | GND / 物理Pin6など | 接続 |

作成するケーブル:

```text
6C Mini TELEM1 Pin1 VCC  -> 未接続、先端を絶縁
6C Mini TELEM1 Pin2 TX   -> Raspberry Pi GPIO15 RXD0 / 物理Pin10
6C Mini TELEM1 Pin3 RX   -> Raspberry Pi GPIO14 TXD0 / 物理Pin8
6C Mini TELEM1 Pin4 CTS  -> 未接続
6C Mini TELEM1 Pin5 RTS  -> 未接続
6C Mini TELEM1 Pin6 GND  -> Raspberry Pi GND / 物理Pin6
```

Pi 40ピンヘッダ側の向き:

```text
Raspberry Pi 40-pin GPIO

物理Pin  6 = GND    -> 6C Mini TELEM1 Pin6 GND
物理Pin  8 = GPIO14 / TXD0 -> 6C Mini TELEM1 Pin3 RX
物理Pin 10 = GPIO15 / RXD0 -> 6C Mini TELEM1 Pin2 TX
```

推奨線色:

```text
TELEM1 Pin1 VCC = 赤、未接続で絶縁
TELEM1 Pin2 TX  = 青、Pi RXD0へ
TELEM1 Pin3 RX  = 黄、Pi TXD0へ
TELEM1 Pin6 GND = 黒、Pi GNDへ
```

Pi側設定候補:

```text
enable_uart=1
シリアルコンソールは無効
MAVLink接続デバイス: /dev/serial0
通信速度: 921600bps候補
```

ArduPilot側設定候補:

```text
SERIAL1_PROTOCOL = 2
SERIAL1_BAUD     = 921
```

注意:

- Piの5VピンへTELEM1の5Vを接続しない。
- PiのGPIOは3.3V UART。5VのUART信号を入れない。
- 先にテスターでGND導通とVCC未接続を確認する。
- 接続後、Pi側で`/dev/serial0`が使える状態か確認してからMAVLink Router / Rpanionを起動する。

2026-06-09:

- Raspberry Pi / MAVLinkの`TELEM1`接続は動作確認OK。
- `TELEM1`の5VはPiへ接続せず、Piは別電源運用とする。
- LiDARは`TELEM2`、Raspberry Piは`TELEM1`として、UARTポート分離済み。

LiDAR UARTの基本配線:

```text
6C Mini TELEMx TX -> LiDAR RX
6C Mini TELEMx RX -> LiDAR TX
6C Mini TELEMx GND -> LiDAR GND
5V給電はLiDARの仕様と消費電流を確認してから接続する
```

### TF-Luna -> 6C Mini TELEM2 6ピン作成メモ

TF-Luna公式ユーザーマニュアルのUART時ピン:

| TF-Luna No. | 機能 | UART時の扱い |
| --- | --- | --- |
| 1 | `+5V` | 電源 |
| 2 | `RXD / SDA` | UART受信 |
| 3 | `TXD / SCL` | UART送信 |
| 4 | `GND` | GND |
| 5 | Configuration Input | UARTでは未接続、または3.3V。GNDへ落とすとI2Cモードになるため接続しない。 |
| 6 | Multiplexing Output | 今回は未使用。 |

線色について:

- `TF-Luna User Manual.pdf` の `6.1 Description about Line Sequence and Connection` / `Table 6` は、ピン番号と機能を定義しており、線色は定義していない。
- BenewakeのQuick Implementation系資料には `1=Red/+5V`, `2=White/RXD-SDA`, `3=Green/TXD-SCL`, `4=Black/GND` の色表記がある。
- ただし、実機作業では線色を主根拠にせず、TF-Lunaコネクタのピン番号と導通確認を優先する。
- 今回の現物ケーブルは公式例と色が異なるため、以下の現物色を使って6C Mini側へ変換する。
- 最新の接写写真では、TF-Lunaコネクタを左から `赤 / 青 / 黄 / 緑 / 白 / 黒` と目視判別できる。
- ただし、最終結線では色だけでなく、TF-Lunaコネクタのピン番号と導通確認を優先する。

現状のTF-Lunaケーブル色:

TF-Luna本体を正面、レンズを上、コネクタを手前、線を下に見た状態で、左から以下の並びとする。

```text
No.1 = 赤 = +5V
No.2 = 青 = RXD / SDA
No.3 = 黄 = TXD / SCL
No.4 = 緑 = GND
No.5 = 白 = Configuration Input
No.6 = 黒 = Multiplexing Output
```

UART運用で使う線:

```text
赤 = +5V
青 = RXD
黄 = TXD
緑 = GND
白 = 未接続
黒 = 未接続
```

Pixhawk 6C Mini `TELEM2` 6ピン:

| 6C Mini `TELEM2` Pin | 機能 | TF-Luna側 | 接続 |
| --- | --- | --- | --- |
| Pin1 | `VCC +5V` | No.1 赤 `+5V` | 接続 |
| Pin2 | `UART5_TX` | No.2 青 `RXD` | 接続。FC TX -> LiDAR RX |
| Pin3 | `UART5_RX` | No.3 黄 `TXD` | 接続。FC RX <- LiDAR TX |
| Pin4 | `UART5_CTS` | - | 未接続 |
| Pin5 | `UART5_RTS` | - | 未接続 |
| Pin6 | `GND` | No.4 緑 `GND` | 接続 |

作成する6ピンコネクタ:

```text
6C Mini TELEM2 Pin1 VCC  -> TF-Luna 赤 +5V
6C Mini TELEM2 Pin2 TX   -> TF-Luna 青 RXD
6C Mini TELEM2 Pin3 RX   -> TF-Luna 黄 TXD
6C Mini TELEM2 Pin4 CTS  -> 未接続
6C Mini TELEM2 Pin5 RTS  -> 未接続
6C Mini TELEM2 Pin6 GND  -> TF-Luna 緑 GND
```

6C Mini側JST-GH 6ピンの推奨線色:

```text
Pin1 VCC  = 赤
Pin2 TX   = 青
Pin3 RX   = 黄
Pin4 CTS  = 未使用
Pin5 RTS  = 未使用
Pin6 GND  = 緑、または黒
```

理由:

- `Pin2 TX`はTF-Lunaの青 `RXD`へ接続するため、6C Mini側も青にすると追いやすい。
- `Pin3 RX`はTF-Lunaの黄 `TXD`から受けるため、6C Mini側も黄にすると追いやすい。
- TF-Luna現物では緑が`GND`なので、緑をTX/RXへ使うと混乱しやすい。
- 黒線を使えるなら、GNDは黒にするのが一般的。TF-Luna側の緑GNDへ接続する。

注意:

- TF-Lunaの5番Configuration Input、現物色では白線はGNDへ接続しない。GNDへ落とすとI2Cモードになる。
- TF-Lunaの6番Multiplexing Output、現物色では黒線は今回未使用。
- TF-LunaはUART既定で115200bps。
- 6C Mini側は`TELEM2`を使う場合、ArduPilot上は`SERIAL2`。
- `SERIAL2_PROTOCOL=9`, `SERIAL2_BAUD=115`で動作確認済み。
- 2026-06-08: Mission Plannerで `Sonar Range (m) = 1.50` の表示を確認。LiDAR / RangeFinderのTELEM2接続は動作確認OK。
