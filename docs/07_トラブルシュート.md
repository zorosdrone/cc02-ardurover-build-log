## 2026-06-09 PM02電圧表示をスモークストッパー経由で確認していた

### 状況

- 実測電圧: 12.40V
- Mission Planner表示: 12.11V
- `BATT_VOLT_MULT=18.182`設定後の画面表示: 12.37V
- ただし、測定時にスモークストッパーを入れていた可能性がある。

### 判断

スモークストッパー経由の電圧は、保護素子や配線抵抗による電圧降下を含む可能性がある。
そのため、上記の12.11V / 12.37VはPM02電圧校正の根拠にしない。

2026-06-09にスモークストッパーなしで再測定した結果、実測12.40V、Mission Planner表示12.44Vだった。
差分は+0.04V、約+0.3%のため、`BATT_VOLT_MULT=18.182`のまま追加補正しない。

### 再確認手順

1. 電源OFF。
2. 配線に短絡や発熱がないことを確認する。
3. 初回保護確認としてスモークストッパーを入れ、異常発熱や異常点灯がないことだけ確認する。
4. 電源OFF。
5. スモークストッパーを外す。
6. PM02経由で通常給電する。
7. LiPo電圧をテスターで測る。
8. Mission Plannerの`Bat1`電圧と比較する。
9. 0.1Vから0.2V以上ずれる場合だけ、`BATT_VOLT_MULT`の補正を検討する。

## 2026-06-08 M8N GPSをGPS2へ接続したがNoGPS

### 状況

- Firmware: ArduRover V4.6.3
- 接続: 現行M8N GPS側6ピンを`GPS2`へ接続

  - `Pixhawk6C`
  - `EKF3 IMU0/IMU1 initialised`

### 判断

FC起動、IMU、EKF、MAG系は動いている。
NoGPSの主な確認対象は、`GPS2`に対応する`SERIAL4`設定、GPS種別設定、GPSへの5V給電、GPS側6ピンコネクタの向きである。

### 確認順

1. Mission PlannerのFull Parameter Treeで以下を確認する。
   - `SERIAL4_PROTOCOL=5`
   - `SERIAL4_BAUD=230`
   - `GPS1_TYPE=1`
2. 変更後、必ずFCを再起動する。
3. M8N本体のLEDが点灯または点滅しているか確認する。
4. GPS2のコネクタを一度抜き、向きと奥まで刺さっているか確認して挿し直す。
5. Mission Plannerの`DATA`画面でGPSステータス、衛星数、HDOPを見る。
6. 屋外または窓際で数分待つ。屋内ではFixしないが、認識していれば衛星数が増えることがある。

標準6ピンコネクタをそのまま`GPS2`へ挿す場合、個別にTX/RXを交差させる作業はしない。
自作変換ケーブルを作る場合だけ、FC側TXとGPS側RX、FC側RXとGPS側TXを対応させる。

### Web資料確認: 新旧PixhawkでGPS 6ピンの+/-が逆か

調査結果:

- 旧Pixhawk / Pixhawk 2.4.8系のGPSポートは、ArduPilot資料上 `Pin 1 = VCC +5V`, `Pin 6 = GND`。
- Pixhawk 6C Miniの`GPS2`は、Holybro公式資料上 `Pin 1 = VCC +5V`, `Pin 6 = GND`。
- Holybro Standard M8N/M9N/M10 GPSのPixhawk1/2.4.6/2.4.8向け6ピンケーブルも、GPS側は `VCC / RX / TX / NC / NC / GND`。
- したがって、資料上は新旧で+/-が逆ではない。

注意:

- 実物で問題になる可能性があるのは、コネクタの上下向き、奥まで刺さっていない、クローン付属ケーブルのピン入れ替え、または接触不良。
- テスター確認では、6C Mini `GPS2`単体の`Pin 1 - Pin 6`間で約+5Vが出るかを見る。
- GPSを挿した状態でLEDが点かない場合は、GPS側コネクタの赤線が`GPS2`のPin 1側に来ているか確認する。
- 2026-06-08追加写真 `photos/wiring/20260608_現行GPSコネクタ_爪下向き確認.JPG` では、現行Pixhawk 2.4.8Pro側のGPSコネクタは爪/キーが下側に見える。
- そのため、一般的な「爪を上にして左から1番」というJST-GH図を、現行Pixhawk 2.4.8Pro側写真へそのまま当てはめない。
- 現行側は、実際に動いていた状態の赤線を+5V側、黒線をGND側として扱い、6C Mini側JST-GHのPin 1/Pin 6へ対応させる。

### Web資料確認: Pixhawk 2.4.8のコネクタ形状

調査結果:

- ユーザー提示の現行Pixhawk Pro購入元は AliExpress item `32947890087`。画像内商品名には `3Line (4P GH1.25, 6P GH1.25, 2.54Pin)` と記載されている。
- ArduPilotの旧Pixhawk資料では、PixhawkのGPSポートは `Pin 1 = VCC +5V`, `Pin 2 = TX`, `Pin 3 = RX`, `Pin 6 = GND`。
- RCToySky保存資料では、3DR GPS+CompassはGPS側を6ピン、MAG/Compass側を4ピンI2Cで接続すると説明されている。
- RCToySky公式サイトのPixhawk2.4.8 & PROポート定義図でも、GPSポートは `5V / TX / RX / ... / GND` 系の並びとして示されている。
- HolybroのM8N資料では、Pixhawk1/2.4.6/2.4.8向けケーブルは `Molex 1.25mm 6pin & 4pin & 3pin` とされている。
- Web上のPixhawk 2.4.8コネクタ情報では、2.4.8クローンはDF13ではなくMolex PicoBlade系を使う例が多いとされている。
- Pixhawk 6C Mini公式資料では、`GPS2`を含む多くのポートはJST-GH 1.25mmである。

判断:

- 旧Pixhawk 2.4.8系GPSコネクタとPixhawk 6C Mini `GPS2`は、ピッチは同じ1.25mmでも、形状規格が違う可能性が高い。
- そのため「一応刺さる」ように見えても、ラッチ、奥行き、端子位置、接触圧が合わず、5V/GNDが接触していない可能性がある。
- GPS LEDが点灯しない現在の症状は、ピン順逆よりも、コネクタ形状違いによる未接触または半挿しの可能性が高い。
- RCToySky公式サイト確認後も、+/-逆よりコネクタ形状違い・接触不良の疑いを優先する。
- 現行Pixhawk 2.4.8Pro側写真ではGPSコネクタの爪が下に見えるため、6C Mini側へ流用するときはコネクタの上下を見た目だけで合わせない。
- 購入元画像では`GH1.25`と表記されているが、AliExpressの商品名表記だけではJST-GH互換性を保証できない。実物の爪位置、奥まで刺さるか、導通、5V/GND接触で判断する。

対応方針:

1. 旧GPSコネクタを6C Miniへ無理に押し込まない。
2. 6C Mini `GPS2`側はJST-GH 6ピン用ケーブルを使う。
3. M8N側のGPS線 `VCC / RX / TX / GND` を、JST-GH 6ピンの `VCC / TX / RX / GND` へ変換する。
4. 現行M8NのCompassは別4ピンI2Cなので、短期的には6C Miniの独立`I2C`へ別途変換する。
5. 変換ケーブル作成後、GPS LED点灯を確認してからMission PlannerでGPS認識を確認する。

### 変換ケーブル購入方針

上下反転だけを目的にした既製変換コネクタは一般的ではない。
無理に「上下変換」「反転変換」を探すより、6C Mini側に合うJST-GH 6ピン/4ピンのピグテールまたはブレークアウトを使い、信号名で結線し直す。

購入候補:

- `JST-GH 1.25mm 6P ピグテール`
- `JST-GH 1.25mm 4P ピグテール`
- `JST-GH 6P to Dupont`
- `JST-GH 4P to Dupont`
- `JST-GH 6P ブレークアウト基板`

GPS用:

```text
6C Mini GPS2 JST-GH 6P
  Pin1 VCC       -> M8N 5V
  Pin2 UART_TX   -> M8N RX
  Pin3 UART_RX   -> M8N TX
  Pin6 GND       -> M8N GND
```

Compass用:

```text
6C Mini I2C JST-GH 4P
  VCC -> M8N Compass 5V
  SCL -> M8N Compass SCL
  SDA -> M8N Compass SDA
  GND -> M8N Compass GND
```

注意:

- 既製ケーブルの線色は信用しない。必ず導通確認でPin番号と線を対応させる。
- Dupont変換はベンチ確認には便利だが、走行時は抜けやすいため、最終配線では固定または圧着済みケーブルにする。

## 2026-06-08 OLED ModuleをI2Cへ接続したが表示されない

### 状況

- 対象: 現行Pixhawk Proセット付属OLED Module
- 接続先: Pixhawk 6C Mini 独立`I2C`
- OLED基板印字: `GND / VCC / SCL / SDA`
- 実物線色:
  - `GND = 黒`
  - `VCC = 赤`
  - `SCL = 緑`
  - `SDA = 黄`
- 症状: ハンダ後、I2Cへ接続したが表示なし
- 結果: `NTF_DISPLAY_TYPE=1`を設定して再起動したところ表示成功

### 設定確認

ArduPilotのオンボードOLED表示は、I2Cへ接続しただけでは表示されない場合がある。
Mission PlannerのFull Parameter Treeで以下を設定して再起動する。

```text
NTF_DISPLAY_TYPE = 1
```

2026-06-08の実機確認では、この設定で表示成功。

表示されない場合は、OLEDコントローラがSH1106系の可能性があるため以下に変更して再起動する。

```text
NTF_DISPLAY_TYPE = 2
```

### 切り分け順

1. FC電源OFF。
2. OLEDだけをI2Cへ接続する。GPS/Compassなど他のI2C機器は一旦外す。
3. 配線を再確認する。

```text
OLED GND / 黒 -> 6C Mini I2C Pin4 GND
OLED VCC / 赤 -> 6C Mini I2C Pin1 VCC
OLED SCL / 緑 -> 6C Mini I2C Pin2 SCL
OLED SDA / 黄 -> 6C Mini I2C Pin3 SDA
```

4. 通電前に`VCC-GND`間がショートしていないことを確認する。
5. 通電後、OLED側の`VCC-GND`間に約5Vが来ているか確認する。
6. `NTF_DISPLAY_TYPE=1`で再起動して確認する。
7. 表示がなければ`NTF_DISPLAY_TYPE=2`で再起動して確認する。
8. どちらも表示されない場合、SCL/SDA逆、I2C接触不良、OLED故障、またはファームウェア側のNotify Display非対応を疑う。

### 注意

- `NTF_DISPLAY_TYPE`がMission Plannerに存在しない場合、そのファームウェア構成ではオンボードOLED表示が使えない可能性がある。
- OLEDは起動直後すぐに表示されない場合があるため、再起動後しばらく待つ。
- I2Cは複数機器を接続できるが、初回はOLED単体で確認する。
