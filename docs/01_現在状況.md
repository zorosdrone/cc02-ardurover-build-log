## 2026-07-26 Lua障害物回避 実機移行追記

SITLで確認済みだったLua状態機械をArduRover 4.6.3実機へ移した結果、状態遷移だけでは実機動作を保証できないことが判明した。

- TF-Lunaは対象なしで`0.00 m / st=2`を返し、0.01～0.02 mも混ざる。
- 保存paramの`RTUN_ENABLE=0`と、Pixhawk実値`1`が一致していなかった。
- 2026-07-26のBINログを解析し、直接スロットル`-0.35`は`RCOU.C3`が約`1448 us`にとどまり、速度も概ね`-0.03～+0.03 m/s`で実質停止だったことを確認した。
- 同じログのManual後退では、約`1401 us`以下で明確な負速度が発生し、`1380～1394 us`で約`-0.3～-0.57 m/s`を記録した。
- 後退失敗の直接原因は、Luaの`-0.35`がESCの有効な後退領域へ届かなかったことと判断した。
- v8.1の`-0.70`で物理後退は成立したが、1.8秒では数cmしか後退せず、操舵`0`のため方位も変わらなかった。
- 後退と操舵を同時出力するv9案は、SITL版の動作確認に誤認があったため実機投入前に撤回した。
- 実機用v9.1はSITL版と同じく、操舵中立で4.5秒直進後退し、その後`0.20 m/s`、`20 deg/s`で4.5秒前進旋回する方式で、一応の回避成功を確認した。
- 実機用v9.2は`SCR_USER2～6`をMission Plannerから変更可能にし、初期値を直進後退`2.25秒`、前進旋回`4.5秒`、旋回速度`0.20 m/s`、旋回率`40 deg/s`、後退スロットル`-0.70`とした。変更値は次回Guided開始時に固定する。

原因、対策、次回の準備は[「SITLから実機移行で起きた問題と再発防止」](03_Lua障害物回避/08_SITLから実機移行で起きた問題と再発防止.md)に記録した。
BINログの数値比較は[「2026-07-26 Lua後退失敗 BINログ解析」](../logs/test_runs/20260726_01_lua_backup_failure_bin_analysis.md)に記録した。

## Lua障害物回避 / SITL準備状況

- Rover SITL前方Rangefinder手順は、実機ファームウェアと同じArduRover 4.6.3基準で整理済み。
- 最新ArduPilotソース / 4.7系以降との差分として、`RNGFND1_MIN` / `RNGFND1_MAX`と`distance_orient()`への読み替えを手順内に残す。
- 仮想ポスト確認はMAVProxyの`script /tmp/post-locations.scr`を主手順にし、`sitl-posts.kml`はMission Planner KMLオーバーレイやKMLビューアでの補助表示に使う。
- `luaoa_rangefinder_watch.lua` は、SITL前方Rangefinderを読み取り、`warn zone` / `stop zone` をGCSへ表示できるところまで確認済み。
- `luaoa_min_guided_avoid.lua` は、`SLOW`、`STOP`、`BACKUP`、`TURN`、`RECHECK`、`RESUME` までの状態遷移を確認済み。
- 2026-06-30版では、標準Rover側で`vehicle:get_target_location()`がTargetを返せない場合に、`vehicle:get_wp_distance_m()`、`vehicle:get_wp_bearing_deg()`、`ahrs:get_location()`、`Location:offset_bearing()`からGuided Targetを復元する方式へ更新した。
- 現在のLua識別文字列は `20260630-wp-vector-target-v6`。起動ログ `LUAOA: loaded 20260630-wp-vector-target-v6` が最新読み込み確認になる。
- 次の主確認は、Fly To送信後に `LUAOA: guided target ready via wp-vector` が出ることと、回避後に `LUAOA: RESUME -> CLEAR: target restored` で復帰できること。

## 残す注意点

- Compass PreArm `Check mag field` は再発することがある。`ARMING_MAGTHRESH=150` は一時緩和候補だが、本運用では方位確認を優先する。
- Mission Planner表示電圧とテスター実測の差は、長時間走行前に再確認する。
- RTL / SmartRTL中にもLiDARは見えているが、障害物停止保証としては扱わない。
- SmartRTLは障害物なし経路限定。
- BendyRuler / `OA_TYPE=1` は実験扱い。河原では評価しない。
- 前方TF-Luna 1個では横方向・後方の安全は見えていない。
- Lua Guided回避はSITL検証段階。実機ではまだ自動後退・旋回を安全確認済みとして扱わない。
- Lua試験時は、QuikTune用`rover-quicktune.lua`など他のLuaと同時実行しない。
- SITLでLuaを差し替えた後は、MAVProxyの`reboot`だけでは古いLuaが残ることがある。確実に確認する場合は`sim_vehicle.py`ごと起動し直す。
