# ログ管理

この資料では、各プロジェクトの試験記録と、大容量ログファイルの保存方針を管理します。

大容量の `.BIN`、`.bin`、`.ulg`、`.tlog` ファイルは通常のGitには直接入れません。

原則:

- チューニング記録は `projects/02_チューニング/logs/test_runs/` に置く。
- Lua障害物回避の記録は `projects/03_Lua障害物回避/logs/test_runs/` に置く。
- `logs/test_runs/` にはMarkdown記録を置き、生ログは置かない。
- 採用済みで再解析価値が高い生ログだけ、該当プロジェクトの `logs/accepted/` に置き、Git LFSで管理する。
- GPS位置、Home位置、走行軌跡を含むログは、公開リポジトリには置かない。
- privateリポジトリでも、共有前に位置情報を含むか確認する。

外部保存またはGit LFS管理する場合は、次の情報を記録します。

- 日時
- 試験場所
- 機体状態
- 使用したパラメータ
- 試験目的
- 外部保存先
- Git LFS管理の有無
- 結果概要
- 次の対応

詳細な走行試験記録は `projects/02_チューニング/logs/test_runs/` に置き、`projects/01_FC換装/07_走行試験.md` から参照します。

## Git LFS対象

`.gitattributes` で、以下だけをGit LFS対象にします。

```text
projects/**/logs/accepted/*.bin
projects/**/logs/accepted/*.BIN
projects/**/logs/accepted/*.ulg
projects/**/logs/accepted/*.tlog
projects/**/logs/accepted/**/*.bin
projects/**/logs/accepted/**/*.BIN
projects/**/logs/accepted/**/*.ulg
projects/**/logs/accepted/**/*.tlog
```

## 採用ログを追加する手順

1. 該当プロジェクトの `logs/test_runs/` にMarkdown記録を作る。
2. 採用ログだけ同じプロジェクトの `logs/accepted/` へコピーする。
3. 位置情報を公開してよいか確認する。
4. `git lfs ls-files` でLFS対象になっていることを確認する。
5. Markdown記録に `logs/accepted/` のファイル名を追記する。
