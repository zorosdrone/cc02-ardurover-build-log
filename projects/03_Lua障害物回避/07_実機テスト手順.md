# Lua障害物回避 実機手順

更新日: 2026-07-27

対象: CC-02、Pixhawk 6C Mini、ArduRover 4.6.3、前方TF-Luna

## 目的

前方障害物を検知したときに、Luaが次の一連の動作を行うことを確認する。

```text
接近
  -> 減速
  -> 停止
  -> 直進後退
  -> 前進しながら固定方向へ旋回
  -> 前方を再確認
  -> 元のGuided目標へ復帰
```

使用するLua:

```text
projects/03_Lua障害物回避/scripts/luaoa_guided_avoid_rover463.lua
```

実機移行で判明したSITLとの差と再発防止策は、[SITLから実機移行で起きた問題と再発防止](08_SITLから実機移行で起きた問題と再発防止.md)を参照する。

通常運用へ戻すパラメータ:

```text
projects/04_WebGCS遠隔操作/params/20260720_01_webapp_rc1_steering_rc3_throttle.param
```

## 1. 試験設定

Mission Plannerで現在のフルパラメータを保存してから、次を設定する。

```text
SCR_ENABLE        = 1
SCR_USER1         = 3
SCR_USER2         = 2.25
SCR_USER3         = 4.5
SCR_USER4         = 0.20
SCR_USER5         = 40
SCR_USER6         = -0.70
RTUN_ENABLE       = 0
AVOID_ENABLE      = 0
AVOID_BACKUP_SPD  = 0
WP_SPEED          = 0.3
```

`AVOID_ENABLE=0`は、ArduPilot標準OAとLuaの動作を重ねないための試験設定である。

`RTUN_ENABLE=0`は現行パラメータファイルに合わせてQuikTuneを無効のままにする設定である。
実機用Lua v9.2は`RTUN_ENABLE`を起動条件にしていないため、QuikTune Luaを削除済みなら、
実機値が`1`でも障害物回避Luaは`FAULT`にしない。

次のSteering／Throttle出力設定は、変更せず試験前に読み取って一致を確認する。

```text
SERVO1_FUNCTION = 26
SERVO1_MIN      = 1100
SERVO1_TRIM     = 1500
SERVO1_MAX      = 1900
SERVO1_REVERSED = 0
SERVO3_FUNCTION = 70
SERVO3_MIN      = 1350
SERVO3_TRIM     = 1500
SERVO3_MAX      = 1750
SERVO3_REVERSED = 0
MOT_SLEWRATE    = 100
```

v9.2は`SERVO1_FUNCTION=26`を確認する。また、`SERVO3_FUNCTION`、`MIN`、`TRIM`、`REVERSED`から`SCR_USER6`の後退出力で`1405 us`以下へ到達できる構成か事前検査する。不一致の場合は走行を開始せず`FAULT`となる。

### Mission Plannerから変更できるLua設定

| パラメータ | 意味 | 初期値 | 許容範囲 |
| --- | --- | ---: | ---: |
| `SCR_USER2` | 直進後退時間 | `2.25 s` | `0.5～10 s` |
| `SCR_USER3` | 前進旋回時間 | `4.5 s` | `0.5～20 s` |
| `SCR_USER4` | 前進旋回速度 | `0.20 m/s` | `0.05～1.0 m/s` |
| `SCR_USER5` | 符号付き旋回率 | `40 deg/s` | 絶対値`5～120 deg/s` |
| `SCR_USER6` | 後退スロットル | `-0.70` | `-1.0～-0.1` |

各値の`0`はスクリプト内の初期値を使用する指定である。Mission Plannerの`Full Parameter List`で変更して`Write Params`する。
変更値は回避途中には反映せず、HOLDまたはDisarm後、次にGuided目標を取得した時点で検査して固定する。Pixhawkの再起動は不要である。

### Mission PlannerからLuaを配置する

作業中はRoverをDisarmし、走行用バッテリーを外しておく。PixhawkはUSB給電だけで起動する。

1. Mission PlannerをPixhawkへ接続する。
2. 上部メニューから`CONFIG`を開く。
3. 左側メニューの`MAVFTP`を開く。
4. ファイル一覧を更新し、SDカードのルートにある`APM`を開く。
5. `APM/scripts`を開く。

`scripts`フォルダが存在しない場合:

1. `CONFIG`の`Full Parameter List`で`SCR_ENABLE=1`を設定する。
2. `Write Params`で書き込む。
3. Pixhawkを再起動する。
4. 再接続して`CONFIG` → `MAVFTP` → `APM`を開き、`scripts`が作成されたことを確認する。

#### 既存Luaを退避する

`APM/scripts`に`.lua`ファイルがある場合は、先にPCへ保存する。

1. `APM/scripts`内のファイル名とサイズを記録する。
2. 各`.lua`を選択し、Mission PlannerのDownload操作でPCへ保存する。
3. 保存先を次のような日付入りフォルダにする。

   ```text
   backup/APM_scripts_YYYYMMDD/
   ```

4. PC側にファイルが存在し、サイズが0 byteでないことを確認する。
5. バックアップできた`.lua`を`APM/scripts`から削除する。
6. 一覧を更新し、`.lua`が残っていないことを確認する。

Mission Plannerの版によってボタン表示が`Download`、`Get`など異なる場合がある。ファイルをPCへ取得する操作を使用する。フォルダ自体やログなど、`.lua`以外のファイルは削除しない。

#### 実機用Luaをアップロードする

1. `APM/scripts`を開いた状態でUpload操作を選ぶ。
2. PC側で次のファイルを選択する。

   ```text
   projects/03_Lua障害物回避/scripts/luaoa_guided_avoid_rover463.lua
   ```

3. 転送完了までMission Plannerを切断しない。
4. MAVFTPの一覧を更新する。
5. 次を確認する。

   ```text
   APM/scripts/luaoa_guided_avoid_rover463.lua
   ```

6. ファイル名の末尾が`.lua`であり、`.lua.txt`になっていないことを確認する。
7. ファイルサイズが0 byteでないことを確認する。
8. `APM/scripts`に存在する`.lua`が、この1本だけであることを確認する。

Pixhawkを再起動する。再接続後、Mission Plannerの`DATA`画面にあるMessagesで次を確認する。

```text
LUAOA463: loaded 20260727-rover463-staged-v9.2
LUAOA463: SCR_USER1 0=monitor 1=stop 2=back 3=full
LUAOA463: SCR_USER2-6 runtime tune; 0=default
```

表示されない場合:

- `SCR_ENABLE=1`が書き込まれているか確認する。
- MAVFTPでファイルが`APM/scripts`直下にあるか確認する。
- ファイル名が`.lua`で終わっているか確認する。
- 他のLuaが同時に置かれていないか確認する。
- Messagesに`Scripting`、`Lua`、`out of memory`などのエラーがないか確認する。
- `reboot`だけで反映されない場合は、Disarmと走行用バッテリー切断を確認してからPixhawkを電源再投入する。

### 物理SDカードを使う場合

MAVFTPを使わず、PixhawkのmicroSDカードへ直接コピーしてもよい。

1. RoverをDisarmし、USBと走行用バッテリーを外す。
2. Pixhawkの電源が切れてからmicroSDカードを抜く。
3. PCでSDカードを開く。
4. `APM/scripts`内の既存LuaをPCへバックアップする。
5. `APM/scripts`から既存の`.lua`を外す。
6. `luaoa_guided_avoid_rover463.lua`を`APM/scripts`へコピーする。
7. `.lua`がこの1本だけであることを確認する。
8. OSの「取り出し」を実行してからSDカードを抜く。
9. SDカードをPixhawkへ戻し、Pixhawkを起動する。
10. Mission PlannerのMessagesで起動識別文字列を確認する。

## 2. 距離確認

TF-Luna正面の1～3 mに板を置き、Mission Plannerの距離表示とLua表示が概ね一致することを確認する。

```text
LUAOA463: monitor ... m st=... lv=3
```

板を近づけると表示距離が小さくなればよい。距離が100倍または1/100になる、値が固定される、距離が出ない場合は走行しない。

この実機のTF-Lunaは、前方に対象がないときに生値`0 cm / st=2`を返す。
実機用Lua v6は表示値を変換せず、距離`0.00 m`を前方障害物なしとして扱う。

```text
LUAOA463: monitor 0.00 m st=2 lv=3
```

正の距離値は従来どおり使用する。例えば`1.53 m / st=4`は1.53 mの障害物として扱う。

## 3. 障害物の配置

- 平坦で石や草の少ない場所を使う。
- TF-Lunaが捉えやすい自立式の板を障害物にする。
- 障害物の左右と後方に、Roverが旋回できる空間を残す。
- Guided目標は障害物の先へ設定できる位置にする。
- 人や車両を障害物として使用しない。

Roverは固定方向へ旋回する。障害物の横に壁、段差、車両などがないことを確認する。

## 4. 回避走行

1. 送信機を保持し、HOLDとDisarmをすぐ操作できる状態にする。
2. Roverを障害物から3.5 m程度離し、正面を障害物へ向ける。
3. HOLDでArmする。
4. Guidedへ変更する。
5. Mission Plannerで障害物の先へGuided目標を送る。
6. 次のログを確認する。

   ```text
   LUAOA463: guided target ready via ...
   LUAOA463: control level 3 latched
   LUAOA463: IDLE -> CLEAR: guided target ready
   ```

7. Roverが最大0.3 m/sで障害物へ接近することを確認する。
8. 約3 mで減速し、約2 mで停止することを確認する。
9. 停止後、操舵中立で直進後退し、その後に前進しながら固定方向へ旋回することを確認する。
10. 旋回後の前方が3.5 m以上空いていれば、元のGuided目標へ復帰することを確認する。

後退中は速度制御ではなく、実機の後退PWM域へ入れるため操舵`0`と直接スロットル`-0.70`を初期値`2.25秒`間出す。
`SERVO3_MIN=1350`、`SERVO3_TRIM=1500`の範囲で制限される。
MessagesにはSteering機能とThrottle機能へ実際に出たPWMも表示される。

```text
LUAOA463: back s=0.00/... t=-0.70/...
```

v9.2はBACKUP開始1.0秒後のPWMを検査する。実ログで確認した後退境界を考慮し、`1405 us`以下へ到達した場合だけ次を表示してBACKUPを継続する。

```text
LUAOA463: back pwm ok 1395; motion unverified
```

この表示はPixhawkの出力契約だけを確認したもので、車輪または車体の後退確認ではない。

PWMを取得できない場合、または`1405 us`より大きい場合は、次のいずれかを表示して`FAULT`停止保持へ入る。

```text
LUAOA463: FAULT backup pwm unavailable
LUAOA463: FAULT backup pwm 1448 > 1405
```

PWMが`1405 us`以下なのに後退しない場合は、ESCの後退設定、ニュートラル、駆動系を確認する。

v9.2の初期値は、回避成功時のv9.1に対して、直進後退時間を`4.5秒`から`2.25秒`へ半減した。
前進旋回時間は`4.5秒`のままとし、旋回率を`20 deg/s`から`40 deg/s`へ増加した。
SITL版と同じくTURN状態で前進しながら旋回し、実際の旋回方向が意図と逆の場合は`SCR_USER5=-40`へ変更する。

Guided開始時に採用値を確認する。

```text
LUAOA463: cfg b=2.25 t=4.50 v=0.20
LUAOA463: cfg r=40.0 q=-0.70
```

後退距離と旋回角度は直接計測していない。後退時間の半減や旋回率の倍増に対し、実距離と実角度が厳密に比例するとは限らない。

TURN中のログ:

```text
LUAOA463: turn r=40.0 s=0.20 p=.../...
```

正常時の状態遷移:

```text
LUAOA463: CLEAR -> SLOW
LUAOA463: SLOW -> STOP
LUAOA463: STOP -> BACKUP
LUAOA463: BACKUP -> TURN
LUAOA463: TURN -> RECHECK
LUAOA463: RECHECK -> RESUME
LUAOA463: RESUME -> CLEAR: target restored
```

旋回後も前方が塞がっている場合:

```text
LUAOA463: RECHECK -> BACKUP: d=... st=... try=1
```

直進後退、前進旋回、前方再確認を最大5回まで繰り返す。
5回目でも前方が3.5 m未満なら、`FAULT max tries`で停止保持となる。

## 5. 合格条件

- Lua表示とTF-Lunaの実距離が概ね一致する。
- 障害物へ接触せず、減速して停止する。
- BACKUP開始1.0秒後にPWMが`1405 us`以下となり、`back pwm ok ...; motion unverified`が出る。
- PWM確認とは別に、車輪の逆回転または車体の後退を目視確認する。
- 初期値では直進後退が2.25秒で終了し、その後の前進旋回が4.5秒で終了する。
- 旋回後に前方が空いている場合だけ走行を再開する。
- `RESUME -> CLEAR: target restored`が出る。
- HOLDとDisarmで試験を終了できる。

## 6. 終了と復帰

1. HOLDへ変更する。
2. Disarmする。
3. 走行バッテリーを外す。
4. Mission Plannerの`CONFIG` → `MAVFTP` → `APM/scripts`を開く。
5. `luaoa_guided_avoid_rover463.lua`をPCへ保存するか、リポジトリに同じファイルがあることを確認してからSDカード上のファイルを削除する。
6. 試験前に退避したLuaを通常運用でも使用する場合は、`backup/APM_scripts_YYYYMMDD/`から`APM/scripts`へ戻す。
7. MAVFTPの一覧を更新し、試験Luaが残っていないことを確認する。
8. 次の現行パラメータを読み戻す。

   ```text
   projects/04_WebGCS遠隔操作/params/20260720_01_webapp_rc1_steering_rc3_throttle.param
   ```

9. Pixhawkを再起動する。
10. Messagesに`LUAOA463: loaded 20260727-rover463-staged-v9.2`が出ないことを確認する。
11. 次の値が戻っていることを確認する。

   ```text
   RCMAP_ROLL        = 1
   RCMAP_THROTTLE    = 3
   RC7_OPTION        = 153
   AVOID_ENABLE      = 7
   AVOID_MARGIN      = 1
   AVOID_BACKUP_SPD  = 0.2
   RNGFND1_MAX_CM    = 400
   RTUN_ENABLE       = 0
   SCR_USER1         = 0
   SCR_USER2         = 0
   SCR_USER3         = 0
   SCR_USER4         = 0
   SCR_USER5         = 0
   SCR_USER6         = 0
   WP_SPEED          = 0.9776623
   ```

## 中止条件

次の場合はHOLDへ変更し、停止後にDisarmする。

- 距離表示が実距離と合わない。
- 意図しない方向へ後退または旋回する。
- 障害物へ接触しそうになる。
- `LUAOA463: internal error`が出る。
- RoverがFAULT後も停止しない。
