# Pi Zero 2 W OV5647カメラのセットアップ・撮影テスト

## 目的

Rover搭載のRaspberry Pi Zero 2 WへKEYESTUDIO 5MPカメラを接続し、次の項目を確認する。

1. Piがカメラセンサーを認識する。
2. `rpicam`アプリケーションからカメラを使用できる。
3. 最大解像度の静止画を撮影できる。
4. 1920×1080、30 fpsのH.264動画を撮影できる。

## 実機条件

| 項目 | 確認値 |
| --- | --- |
| 確認日 | 2026-08-03 |
| Raspberry Pi | Raspberry Pi Zero 2 W |
| ホスト名 | `pizero2` |
| CPUアーキテクチャ | `aarch64` |
| OS | Debian GNU/Linux 12（Bookworm） |
| カーネル | `6.6.62` |
| カメラ | KEYESTUDIO 5MP固定焦点カメラ |
| センサー | OmniVision `OV5647` |
| 最大静止画解像度 | 2592×1944 |
| 接続 | CSI、15ピン－22ピンのPi Zero用ケーブル |
| PiのTailscale IP | `100.67.15.67`（確認時点） |

PiはRoverのRpanion用コンパニオンコンピュータとして使用している。カメラ確認ではArduPilotパラメータ、Rpanion設定、MAVLink設定を変更しない。

## 1. ケーブル接続

### 使用するケーブル

Pi Zero 2 Wのカメラ端子は細い22ピン、カメラ基板側は広い15ピンである。付属品のうち、15ピン－22ピンのPi Zero用カメラケーブルを使用する。

### 正しい向き

- 細い22ピン側をPi Zero 2 Wへ接続する。
- 広い15ピン側をカメラ基板へ接続する。
- Pi側は、ケーブルの露出した金属接点をPi基板側へ向ける。
- カメラ側も、ケーブルの露出した金属接点をカメラ基板側へ向ける。
- ケーブルを斜めにせず、端子の奥まで水平に入れてロックする。

カメラケーブルの抜き差しは、Piをシャットダウンして電源を外した状態で行う。通電中にCSIケーブルを抜き差ししない。

今回、Pi側のケーブルが逆向きだった状態ではセンサーが認識されなかった。向きを修正して再起動後、`ov5647`が認識された。

## 2. Windows PCからPiへ接続

### Tailscale状態確認

PowerShellで実行する。

```powershell
tailscale status
tailscale ping --c 3 pizero2
```

### SSH接続

このPCでは既存のSSH鍵を使用できたため、Piのログインパスワードは不要だった。初回接続時は提示されたホスト鍵を登録する。

```powershell
ssh -o StrictHostKeyChecking=accept-new pi@100.67.15.67
```

通常の再接続は次でよい。

```powershell
ssh pi@100.67.15.67
```

Tailscale IPは将来変わる可能性があるため、接続できない場合は`tailscale status`で現在値を確認する。

### OS確認

PiへSSH接続後に実行する。

```bash
hostname
uname -m
grep -E '^(PRETTY_NAME|VERSION_CODENAME)=' /etc/os-release
uptime
```

## 3. OSによるセンサー認識確認

### I2Cデバイス名

```bash
for f in /sys/bus/i2c/devices/*/name; do
  grep -H -Ei 'ov5647|imx|camera' "$f" 2>/dev/null || true
done
```

正常時の実機出力は次のとおりだった。

```text
/sys/bus/i2c/devices/10-0036/name:ov5647
```

### Media Controller構成

```bash
for m in /dev/media*; do
  echo "--- $m"
  media-ctl -d "$m" -p 2>/dev/null \
    | grep -Ei 'driver|model|ov5647|unicam' || true
done
```

正常時は`unicam`と`ov5647 10-0036`が接続された状態で表示された。

```text
driver          unicam
model           unicam
- entity 1: ov5647 10-0036 (1 pad, 1 link)
        -> "unicam-image":0 [ENABLED,IMMUTABLE]
```

### 起動ログ

```bash
sudo dmesg | grep -Ei 'ov5647|unicam|camera' | tail -n 60
```

Bookwormの`libcamera`構成では、旧方式の`vcgencmd get_camera`だけで判定しない。最終判定には、上記のセンサーノードと`rpicam-hello --list-cameras`を使う。

## 4. カメラアプリケーションの確認と修復

### 導入済みパッケージ確認

```bash
dpkg -l | grep -E 'libcamera|libpisp|rpicam|picamera'
apt-cache policy \
  rpicam-apps-lite \
  libcamera0.3 \
  libcamera-ipa \
  libpisp1
```

### 修復前のエラー

```bash
rpicam-hello --list-cameras
```

修復前は次のシンボル解決エラーで`rpicam-hello`が起動しなかった。

```text
rpicam-hello: symbol lookup error: /lib/aarch64-linux-gnu/libcamera.so.0.3:
undefined symbol: _ZN7libpisp22compute_optimal_strideER24pisp_image_format_config
```

センサー未認識とは別に、`rpicam-apps-lite`、`libcamera`、`libpisp`の版が整合していない状態だった。

### 今回実行した修復

```bash
sudo apt-get install -y \
  rpicam-apps-lite \
  libcamera-ipa \
  gstreamer1.0-libcamera \
  python3-libcamera
```

実行結果は、4パッケージ更新、依存する3パッケージの新規導入、削除なしだった。

主な更新後バージョンは次のとおり。

```text
libcamera-ipa       0.5.2+rpt20250903-1~bpo12+1
libcamera0.5        0.5.2+rpt20250903-1~bpo12+1
rpicam-apps-lite    1.9.0-1~bpo12+1
rpicam-apps-core    1.9.0-1~bpo12+1
```

`apt`から旧`libcamera0.3`などが自動削除可能と表示されたが、今回の確認では`apt autoremove`を実行していない。

## 6. 静止画撮影テスト

### 撮影

```bash
rm -f /tmp/rover-camera-test.jpg
rpicam-still \
  --nopreview \
  --timeout 3000 \
  --output /tmp/rover-camera-test.jpg
```

### ファイル確認

```bash
file /tmp/rover-camera-test.jpg
stat -c '%n %s bytes' /tmp/rover-camera-test.jpg
sha256sum /tmp/rover-camera-test.jpg
```

確認結果は次のとおり。

```text
JPEG image data, 2592x1944
710897 bytes
SHA-256: 4d03ab93725a39e2e5e944b390814751bcee7cffc8b7e88dc52bf3ed7068769b
```

撮影画像を目視し、色、露出、ピント、ケーブル不良を示す縞や欠損に目立つ異常がないことを確認した。

## 7. 1080p動画撮影テスト

### 撮影

```bash
rm -f /tmp/rover-camera-test.h264
rpicam-vid \
  --nopreview \
  --timeout 5000 \
  --width 1920 \
  --height 1080 \
  --framerate 30 \
  --codec h264 \
  --output /tmp/rover-camera-test.h264
```

### ファイル確認

```bash
file /tmp/rover-camera-test.h264
stat -c '%n %s bytes' /tmp/rover-camera-test.h264
sha256sum /tmp/rover-camera-test.h264
```

確認結果は次のとおり。

```text

5690760 bytes
SHA-256: 051e4ee80fd4fa1e5adf248bbc83af48e82234fbbd66fde0f7b8533c9595d44c
```

## 8. Windows PCへの取得とMP4化

PowerShellで実行する。以下はサブプロジェクトの`images/`と`videos/`へ保存する例である。

```powershell
$ProjectDir = 'C:\Users\ta1na\source\cc02-ardurover-build-log\projects\07_PiZero2Wカメラ'
$ImageDir = Join-Path $ProjectDir 'images'
$VideoDir = Join-Path $ProjectDir 'videos'
New-Item -ItemType Directory -Force -Path $ImageDir, $VideoDir

scp pi@100.67.15.67:/tmp/rover-camera-test.jpg `
  "$ImageDir\rover-camera-test.jpg"

scp pi@100.67.15.67:/tmp/rover-camera-test.h264 `
  "$VideoDir\rover-camera-test.h264"
```

H.264の映像を再エンコードせず、MP4コンテナへ格納する。

```powershell
ffmpeg -y `
  -framerate 30 `
  -i "$VideoDir\rover-camera-test.h264" `
  -c copy `
  -movflags +faststart `
  "$VideoDir\rover-camera-test.mp4"
```

MP4の情報を確認する。

```powershell
ffprobe -v error `
  -show_entries stream=codec_name,width,height,r_frame_rate `
  -show_entries format=duration,size `
  -of default=noprint_wrappers=1 `
  "$VideoDir\rover-camera-test.mp4"
```

今回のMP4確認結果は次のとおり。

```text
codec_name=h264
width=1920
height=1080
r_frame_rate=30/1
duration=4.533288
size=5693098
```

`--timeout 5000`には初期化時間も含まれるため、実ファイルの再生時間は約4.53秒だった。

## 9. 再確認用の最短コマンド

通常の起動後にカメラを短時間で確認する場合は、Piで次を実行する。

```bash

rpicam-still --nopreview --timeout 3000 -o /tmp/camera-check.jpg
rpicam-vid --nopreview --timeout 5000 \
  --width 1920 --height 1080 --framerate 30 \
  --codec h264 -o /tmp/camera-check.h264
```

## 10. トラブルシュート

### PiがTailscaleへ復帰しない

1. Piの電源を外す。
2. カメラケーブルを外してPi単体で起動する。
3. Pi単体で復帰する場合は、ケーブルの向き、斜め挿入、ロック状態を再確認する。
4. ケーブルを直す際は、必ずPiの電源を外す。

### `ov5647`が表示されない

- Pi側は金属接点がPi基板側になっているか。
- カメラ側は金属接点がカメラ基板側になっているか。
- 22ピン側がPi、15ピン側がカメラになっているか。
- `/boot/firmware/config.txt`に`camera_auto_detect=1`があるか。
- ケーブルが端子の奥まで水平に入っているか。

### `rpicam-hello`がシンボルエラーになる

物理接続の問題と混同せず、`dpkg -l`と`apt-cache policy`で`rpicam`、`libcamera`、`libpisp`の版を確認する。今回と同じエラーの場合は、「4. カメラアプリケーションの確認と修復」の限定更新を実施する。

## 11. 確認範囲

今回確認できたのは、OSによるセンサー認識、静止画撮影、ローカルH.264動画記録までである。Rover走行中の振動、屋外の逆光、低照度、連続記録時間、ネットワーク映像配信は未確認であり、別試験として扱う。
